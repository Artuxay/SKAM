# СКАМ

**Системный Координированный Альтернативный Мессенджер.** Новый виток в развитии русских интернациональных мессенджеров и безопасный аналог МАКС, который будет ловить даже в туалете, а не только на парковке.

Не развод, а мессенджер.

Веб-приложение на **Vite + TypeScript** без фреймворка и **Supabase** (Postgres + RLS, Auth, Realtime, Storage). Ставится на телефон как PWA.

**Адрес: https://skam-messenger.ru.** С версии 0.3.0 СКАМ целиком работает на своём сервере в Москве (Selectel): сайт, база данных, вход, файлы и функции — self-hosted Supabase. Как устроен сервер — в [server/README.md](server/README.md). Старый адрес `artuxay.github.io/SKAM` перенаправляет на новый.

**Версия 0.3.3** (8 октября 2026). Номер версии — `релиз.неделя.день`: первая цифра — релиз (пока `0`), вторая — недельное обновление, третья — обновление по дням внутри недели; прежние 1.0.0 … 1.6.0 стали 0.2.0 … 0.3.1. В 0.3.3 — звонки как в Discord: «Голос и видео», рация, показ экрана с выбором качества, групповые звонки и градиентный фон. В 0.3.1 (6 октября) — новый дизайн, истории, «Заблокировать», «Без звука» и уведомления. Что вошло и как СКАМ рос — в [CHANGELOG.md](CHANGELOG.md).

## Что умеет

- Регистрация и вход как в Telegram: почта (или номер телефона, когда в Supabase подключён SMS-провайдер) → код из письма/SMS → для нового человека экран «Создание аккаунта»: фото, имя, фамилия и @username.
- **Вход через Яндекс ID и VK ID** — кнопки под полем почты («или» → «Войти через Яндекс ID», «Войти через VK ID»). GitHub и Discord убраны: с 7 июля 2026 года российским сайтам нельзя пускать людей через иностранные сервисы входа (ст. 13.55 КоАП). Кнопки показываются только для тех провайдеров, чьи ключи заданы в секретах функции `oauth-login` (см. «Настройка Supabase», п. 9): задали — кнопка появилась сама, без пересборки. Тот, через кого входили на этом устройстве в прошлый раз, стоит первым с пометкой «в прошлый раз». Вход защищён PKCE и проверкой `state`; код провайдера сайт сразу стирает из адресной строки. Новому человеку имя и фамилия подставляются из профиля провайдера, логин Яндекса — в @username (если свободен), фото можно взять оттуда же кнопкой «Взять фото из Яндекс ID» (без нажатия чужое фото не ставится). Если почта у провайдера та же, что у аккаунта в СКАМ, вход попадает в тот же аккаунт. Если VK не дал почту, аккаунт всё равно создаётся (со служебным адресом, который нигде не показывается), а входить в него можно через VK ID. В профиле видно, как можно войти: «Вход: почта, Яндекс ID». Отмена у провайдера или ошибка — понятное сообщение на экране входа. Кто входил через GitHub или Discord, входит по коду на ту же почту — аккаунт тот же.
- **Пользовательское соглашение и Политика конфиденциальности** — отдельные страницы сайта: [terms.html](https://skam-messenger.ru/terms.html) и [privacy.html](https://skam-messenger.ru/privacy.html), с содержанием, в светлой и тёмной теме, удобно читаются с телефона. При создании аккаунта нужно поставить галочку «Я принимаю Пользовательское соглашение и ознакомлен(а) с Политикой конфиденциальности»: без неё аккаунт не создаётся, по умолчанию она не отмечена. Тем, кто зарегистрировался раньше или принял прошлую редакцию, при следующем входе один раз показывается экран «Правила СКАМ» с кнопкой «Принимаю» (или «Не принимаю — выйти из аккаунта»). Какую редакцию человек принял и когда — записывается на сервере. Ссылки на оба документа есть на экране входа и в профиле, в разделе «О приложении».
- **@username обязателен.** Без него база не даёт писать сообщения, создавать чаты и загружать файлы (`private.is_registered()`), а стереть его нельзя (триггер `profiles_guard`). Тем, кто зарегистрировался раньше без @username, при входе один раз показывается экран «Выберите имя пользователя» — с готовыми свободными вариантами из имени и фамилии. Для отдельных аккаунтов можно сделать исключение (см. «Исключения из обязательного @username»).
- Профиль: имя, фамилия, @username (проверка «свободно/занято» на лету), аватарка (обрезается до квадрата 256×256 и загружается в Supabase Storage) и **«О себе»** — до 140 символов и 5 строк, ссылки нажимаются. «О себе» видят все: в карточке человека — даже без общего чата.
- **Свои ники для людей — как «имя контакта» в Telegram.** В карточке человека — «Дать ник» (до 64 символов, можно с эмодзи). Ник видите **только вы**, и он стоит везде вместо имени: в списке чатов, шапке, подписях в группах, участниках, ответах, пересланных, звонках и поиске. По нику и по настоящему имени человек находится в поиске — даже если личного чата с ним нет («Чаты и контакты»). В карточке под ником мелко — настоящее имя. «Изменить ник» → «Убрать» возвращает имя. Ники хранятся на сервере: одинаковые на всех ваших устройствах.
- **Истории — как в Telegram.** Над списком чатов — лента кружков: «Вы» (своя история и «+») и люди, у которых есть свежие истории. Градиентное кольцо — есть непросмотренные, серое — всё посмотрено. Такое же кольцо у человека в списке чатов, в шапке личного чата и в его карточке: нажали на аватарку — открылись истории.
  - История — **фото, видео до 60 секунд или текст на градиентном фоне** (8 фонов в цветах СКАМ). К фото и видео — подпись до 200 символов. «+» в ленте, «Новый чат» → «Новая история» или плитка «Новая» в профиле. Фото сжимаются до 1080×1920, метаданные снимков не сохраняются.
  - **Видят все, с кем у автора есть личный чат.** Через 24 часа история исчезает — кроме закреплённых в профиле («⋯» → «Закрепить в профиле», до 50). Закреплённые и свежие истории видны в карточке человека и в своём профиле («Мои истории»).
  - Просмотр: полоски прогресса, касание слева — назад, справа — вперёд, удержание — пауза, смахнуть вбок — к следующему человеку, вниз — закрыть (на телефоне), ← → и пробел на клавиатуре. После своих историй — следующие непросмотренные.
  - Ответ на историю — только **сердечко**. Автор видит «N просмотров», а по нажатию — кто смотрел и кому понравилось.
- **Стикеры.** Официальный набор «Голубь свободы» — маскот СКАМ, 16 стикеров. Смайлик внутри поля ввода (справа) открывает панель (с разделом «Недавние»); если набрать эмодзи (👋, 😂, 🤔…), подходящие стикеры появятся над полем ввода сами. В списке чатов стикер виден как «👋 Стикер».
  - **Свои (неофициальные) стикеры.** В панели стикеров кнопка «+» → «Создать набор»: название, картинки (PNG, WebP, JPG или GIF — приложение само уменьшит их до 512 px и сожмёт в WebP до 500 КБ) и эмодзи к каждой. До 120 стикеров в наборе. Особых меток у таких наборов нет — пометка «официальные» только у «Голубя свободы».
  - Своим набором можно поделиться ссылкой `…/?stickers=<id>`, а чужой стикер в чате — нажать: откроется весь набор с кнопкой «Добавить N стикеров» (и отправкой по нажатию). Добавленные наборы появляются в панели и в подсказках по эмодзи; «Убрать из моих стикеров» — там же.
  - Свой набор — карандаш в панели или «+» → «Мои наборы»: добавить стикеры, сменить эмодзи, удалить стикер, переименовать, скопировать ссылку, удалить набор. Удалили набор — в старых сообщениях вместо картинки останется «👋 Стикер».
- **Официальные галочки.** Розетка в цветах логотипа рядом с именем — настоящий аккаунт или канал, а не подделка. Её видно в списке чатов, в шапке, в профиле, в «О канале», в поиске (люди и каналы с галочкой — выше тёзок) и у имени автора сообщения. Выдают и снимают галочки **только владельцы СКАМ**: в профиле человека — кнопка «Выдать галочку» / «Снять галочку», в «О канале» — переключатель «Официальная галочка» (даже без подписки: откройте публичный канал через поиск). Сам себе галочку не поставит никто — ни через интерфейс, ни через API. У канала «Новости СКАМ» и у бота СКАМ галочка есть всегда (см. «Официальные галочки и владельцы СКАМ»).
- **Голосовые** — как в Telegram: удерживайте микрофон справа от поля ввода и отпустите, чтобы отправить; уведите палец влево — отмена, вверх — запись «закрепится», и руки свободны. С клавиатуры: Enter на кнопке — запись, Escape — отмена. До 10 минут, с «волной» громкости, перемоткой, скоростью 1× / 1,5× / 2× и воспроизведением подряд.
- **Кружочки** — короткое нажатие на микрофон превращает его в камеру, дальше так же: удерживайте. До 60 секунд, квадрат 400×400. В ленте кружочек крутится без звука, по нажатию — со звуком и кольцом прогресса.
- Пока собеседник записывает, в шапке чата видно «записывает голосовое…» или «записывает кружочек…».
- **Сквозное шифрование** личных чатов и групп: текст, фото, видео, файлы, стикеры, голосовые и кружочки шифруются в браузере отправителя (WebCrypto: ECDH P-256, HKDF, AES-256-GCM) и расшифровываются только у участников — на сервере лежит шифротекст. Ключ хранится на устройствах, на новом устройстве восстанавливается **паролем шифрования** (его задают один раз при первом входе). Новые участники группы получают историю, а после выхода участника группа переходит на новый ключ. Канал новостей и чат с ботом — без сквозного шифрования, как каналы и боты в Telegram. Старые сообщения остаются как были. Подробно — в [ШИФРОВАНИЕ.md](ШИФРОВАНИЕ.md).
- **Фото, видео и файлы** как в Telegram: скрепка слева от поля ввода, перетаскивание в чат или вставка из буфера. Окно отправки с предпросмотром, подписью и галочкой «Сжать фото и видео» (фото до 2048 px, геометка стирается; без галочки — оригиналы файлами). До 10 вложений в одном сообщении (альбом), до 50 МБ на файл, прогресс загрузки и отмена прямо в пузыре. Просмотрщик фото и видео на весь экран со стрелками и скачиванием; документы скачиваются под своим именем. Каждый файл шифруется своим ключом ещё до загрузки.
- Тема: «Мой профиль» → «Оформление» — «Авто» (как в системе), «Светлая» или «Тёмная».
- **Поиск над списком чатов — как в Telegram.** Сверху слева поле «Поиск»: сначала «Чаты» — ваши личные чаты, группы, каналы и бот СКАМ (по названию, имени собеседника и @username; бота находит и слово «бот»), ниже «Глобальный поиск» — люди и публичные каналы со всего СКАМ (от 2 символов). Совпадения подсвечены, ↑/↓ и Enter выбирают строку, Esc очищает поиск. Человек из глобального поиска открывается профилем с кнопкой «Написать».
- **Папки с чатами — как в Telegram.** Папки — вкладками над списком чатов («Все», ваши папки с числом непрочитанных, настройки); пока своих папок нет, там вкладки «Все», «Личные», «Группы», «Каналы», а папку создают в «Мой профиль» → «Папки с чатами» или правой кнопкой по вкладке. В папку кладут целые типы (личные чаты, группы, каналы, боты) и/или выбранные чаты, можно исключить отдельные чаты и прочитанные. Значок — эмодзи на выбор или «Авто». Есть рекомендуемые папки («Непрочитанные», «Личные», «Группы», «Каналы»), порядок меняется стрелками в «Папках с чатами» или перетаскиванием вкладок мышью. Правой кнопкой мыши (или долгим нажатием) на чат — «Добавить в папку» с галочками и «Новая папка», в папке — «Убрать из папки». Папки хранятся на сервере: одинаковые на всех устройствах, видите их только вы. До 20 папок.
- **Закреплённые чаты.** Правой кнопкой мыши или долгим нажатием на чат → «Закрепить»: чат встаёт наверх списка с булавкой. До 10 закреплённых в «Все чаты» и до 10 в каждой папке (в папке — свои, как в Telegram). Порядок меняется перетаскиванием мышью. Там же — «Отметить прочитанным».
- Поиск людей по имени, фамилии или @username прямо во время набора: «Новый чат» → «Написать человеку». Каждое слово запроса ищется с начала имени, фамилии или @username («арт», «артур гай», «гайнатуллин артур», «artux»), регистр и «ё/е» не важны; «@artux» — только по @username. Сначала показываются те, с кем уже есть общий чат.
- Статусы как в Telegram: внизу слева только вы и «в сети»; в личном чате под именем собеседника — «в сети» или «был(а) в сети … », а пока он пишет — «печатает…».
- Чаты: групповые, личные («Написать» в карточке участника), **каналы**, канал **«Новости СКАМ»** (подписаны все) и **бот СКАМ**, который здоровается с новичками и отвечает на «привет» и «помощь».
- **Каналы и группы как в Telegram.** «Новый чат» → «Новая группа» или «Новый канал»: фото (или значок), название, описание. У канала дальше — «Тип канала»: **публичный** (ссылка `…/?c=имя`, канал находят в поиске, посты видно ещё до подписки — внизу кнопка «Подписаться») или **частный** (только по ссылке-приглашению). Потом — «Добавить участников/подписчиков»: галочками выбираются **знакомые** (те, с кем есть общий личный чат или группа), остальных зовут строкой «Пригласить по ссылке».
  - Посты канала идут от имени канала; по желанию — «Подписывать сообщения» (под постом имя автора). Пост можно **изменить** (у него появится «изменено»).
  - **Администраторы с правами**, как в Telegram. В канале: изменение профиля канала, публикация сообщений, изменение чужих публикаций, удаление чужих публикаций, добавление подписчиков, блокировка подписчиков, назначение администраторов. В группе: изменение профиля группы, удаление сообщений, блокировка пользователей, пригласительные ссылки, назначение администраторов. Выдать можно только те права, что есть у тебя; админ управляет только теми, кого назначил сам, остальными — владелец. Владелец может **передать права** другому администратору.
  - «О канале / О группе»: фото (нажать на него — сменить), описание, ссылка, «Изменить», «Добавить…», а для администраторов — «Тип канала», «Подписывать сообщения», «Администраторы», «Подписчики» (со поиском) и **«Чёрный список»**: удалённый из канала или группы не вернётся по ссылке, пока его не разблокируют. Владелец может удалить канал или группу для всех.
  - Шифрование групп не меняется: удалить участника может админ, а следующее сообщение в группе уйдёт новым ключом, которого у удалённого нет. Фото, название и описание группы, как и раньше название, хранятся открыто.
- Сообщения: реакции 👍 😂 🔥 😱 🤡, удаление своих сообщений, ссылки кликабельны, подгрузка истории при прокрутке вверх.
- **Ответить и переслать — как в Telegram.** Над сообщением (при наведении) есть ↩ «Ответить» и ↪ «Переслать»; правая кнопка мыши (на телефоне — касание или долгое нажатие) открывает меню: реакции, «Ответить», «Копировать текст», «Переслать», «Выбрать», «Удалить». На телефоне можно просто смахнуть сообщение влево — это ответ. С клавиатуры: Ctrl+↑ / Ctrl+↓ в пустом поле выбирают, на что ответить, Esc — отмена.
  - Ответ показывает цитату (автор, текст, миниатюра фото или стикера); нажатие на цитату прокручивает к оригиналу и подсвечивает его, даже если он далеко в истории. Удалили оригинал — в цитате «Сообщение удалено».
  - «Переслать» открывает список чатов с поиском и галочкой «Скрыть имя отправителя». В выбранном чате над полем ввода появляется «Переслать сообщение» — можно дописать комментарий (он уйдёт первым) или сразу нажать «Отправить». У пересланного — «Переслано от Имя» (из канала — «Переслано из Новости СКАМ»); если переслать пересланное, остаётся исходный автор.
  - «Выбрать» включает выбор нескольких сообщений: внизу «Выбрано: N», «Переслать» и «Удалить» (если все выбранные — ваши).
  - Пересылаются текст, стикеры, фото, видео, файлы, голосовые и кружочки. Зашифрованный файл копируется в папку чата-получателя как есть — ключ переезжает внутри нового сообщения, скачивать и загружать заново ничего не нужно. Голосовые и кружочки при пересылке между зашифрованным и открытым чатом расшифровываются и загружаются заново.
- **Звонки — как в Discord.** В шапке личного чата или группы — 📞 «Позвонить» и 📹 «Видеозвонок».
  - У собеседника появляется окно входящего звонка (с мелодией, вибрацией на телефоне и «📞 Входящий звонок» в заголовке вкладки): «Принять», «С видео», «Отклонить» или крестик — скрыть, не отклоняя.
  - В чате над перепиской — сцена звонка на спокойном градиентном фоне: плитки участников 16:9 (видео или аватар) ровной сеткой под любое число людей, зелёная рамка у того, кто говорит, значки выключенного микрофона и звука, таймер. Кнопки: камера, показ экрана (на компьютере), микрофон, звук (выключить звук = как в Discord, и микрофон тоже), «Голос и видео», «Отключиться»; стрелка у микрофона и камеры — быстрый выбор устройства. Сцену можно растянуть за нижний край или развернуть на всю беседу; двойное нажатие на плитку — на весь экран; правая кнопка (на телефоне — долгое нажатие) по плитке — громкость этого участника.
  - **«Голос и видео»** (шестерёнка в звонке или «Мой профиль» → «Голос и видео»): микрофон, камера и динамики списком; громкость микрофона и звонка; «Голосовая активность» с полоской голоса и порогом (вручную или автоматически) либо «Рация» — клавиша по выбору, по умолчанию `V` (работает, пока вкладка СКАМ в фокусе); проверка микрофона («Слышать себя»), предпросмотр камеры; шумоподавление, эхо и автоусиление.
  - **Показ экрана:** перед показом — выбор разрешения (720p / 1080p / исходное), частоты (15 / 30 / 60 к/с) и звука; пока показываете — плашка «Вы показываете экран» с «Качество» и «Остановить». У зрителей экран крупно, остальные участники — лентой под ним, отдельная громкость трансляции и «На весь экран».
  - Звонок не мешает переписке: уйдите в другой чат — внизу слева останется панель «Голосовая связь подключена» с кнопками и задержкой в мс; на телефоне — зелёная полоска «вернуться к звонку». Горячие клавиши: Ctrl+Shift+M — микрофон, Ctrl+Shift+D — звук.
  - В группе к идущему звонку можно присоединиться в любой момент (плашка «Идёт звонок — Присоединиться» и кнопка в ленте), до 8 человек; «Позвонить ещё раз» — тем, кого нет. Если двое звонят друг другу одновременно, они попадают в один звонок. С другого устройства можно «перехватить» звонок — первое отключится.
  - В ленте остаётся запись, как в Telegram: «Исходящий звонок · 5 мин», «Входящий видеозвонок · 12 мин», «Пропущенный звонок», «Отклонённый звонок», «Нет ответа», «Групповой звонок…» — с кнопкой «Перезвонить»; в списке чатов — то же одной строкой.
  - Звук и видео идут **напрямую между участниками** (WebRTC, DTLS-SRTP) и через сервер СКАМ не проходят. Служебные данные соединения шифруются ключом чата, поэтому сервер не может подменить ключи и подслушать. Подробно — в [ШИФРОВАНИЕ.md](ШИФРОВАНИЕ.md), раздел 13.
- **Поддержка.** «Мой профиль» → «Поддержка» открывает окно: тема («Ошибка», «Вопрос», «Идея», «Другое»), текст до 4000 символов и галочка «Приложить сведения об устройстве» — что именно уйдёт (версия СКАМ, браузер, система, экран, язык, часовой пояс, тема, сеть), видно тут же. Обращение получает номер и приходит письмом на ящик СКАМ — тот же, с которого приходят коды для входа; в письме имя, @username и почта человека, а «Ответить» отвечает прямо ему. Черновик не пропадает, если закрыть окно. Не больше 3 обращений за 10 минут и 10 в сутки.
- **Оценить СКАМ.** «Мой профиль» → «Оценить СКАМ»: средняя оценка, число оценок и распределение по звёздам, как в магазине приложений, и своя оценка от 1 до 5 звёзд — её можно поменять в любой момент. Кто сколько поставил, не видит никто. За 1–3 звезды окно предложит написать в поддержку.
- Непрочитанные: счётчики в списке чатов, число в заголовке вкладки и на иконке PWA, отметки ✓ / ✓✓ (прочитано).
- **«Заблокировать»** — в карточке человека или в меню «⋮» личного чата. Как в Telegram: в личном чате с заблокированным нельзя писать и звонить (обоим), он не видит ваши истории, а вы — его; вместо поля ввода — «Вы заблокировали … · Разблокировать». Группы и каналы не затрагиваются. Список — «Мой профиль» → «Конфиденциальность» → «Заблокированные». Проверяет база: `private.can_post` (сообщения и вложения), `call_start` / `call_join`, видимость историй.
- **«Без звука»** — для любого чата на час, 8 часов, 2 дня или навсегда: меню «⋮» в шапке, правая кнопка по чату в списке, плитка в карточке человека. Чат не звенит и не показывает уведомления, его счётчик серый и не входит в общее число непрочитанных. Хранится на сервере — одинаково на всех устройствах.
- **Уведомления о сообщениях:** короткий звук, пока СКАМ открыт, и уведомление системы, когда он свёрнут или в другой вкладке — с текстом сообщения или просто «Новое сообщение». Нажали — открылся чат. Включаются в «Мой профиль» → «Уведомления» (браузер спросит разрешение). Работают, пока СКАМ открыт во вкладке или как приложение; пуш-уведомлений в закрытый СКАМ пока нет.
- **Поиск по чату** — лупа в шапке (на телефоне — в меню «⋮»): совпадения по тексту и названиям файлов, Enter — раньше, Shift+Enter — позже, догружает более ранние сообщения.
- Приватность: профиль и статус человека видят только те, с кем у него есть общий личный или групповой чат. Подписка на канал не считается: подписчики канала не видят друг друга, список подписчиков видят только администраторы. Автора поста до подписки не видно. Общего списка «кто в сети» нет.
- Realtime: новые сообщения, реакции и изменения приходят сразу, есть «печатает…». Статус «в сети» держится пульсом: приложение раз в 45 секунд вызывает `ping()`, при закрытии вкладки сразу ставит «был(а) в сети». Если WebSocket недоступен, изменения подтягиваются опросом раз в 8 секунд.
- **Дизайн 0.3.1** — минималистичный: чёрный, белый и оранжевый `#E85002`; янтарь `#FFAB1A` — звёзды, зелёный `#66EA1B` — «в сети». Логотип прежний, градиент — янтарь → оранжевый → зелёный. Список чатов и переписка — две скруглённые панели. Свои сообщения — в градиенте от янтаря к оранжевому, у официальных чатов (бот СКАМ, «Новости СКАМ») аватарки в градиенте логотипа. В личных чатах у входящих нет аватарки и имени. Окна (профиль, «О чате», «Новый чат», истории) открываются на плавно размытом фоне.
  - Над списком — вкладки «Все», «Личные», «Группы», «Каналы» с числом непрочитанных (со своими папками — вкладки папок). Внизу слева — карточка «я»: аватарка с точкой «в сети», имя и шестерёнка.
  - **«Мой профиль»**: фото с камерой, имя, @username, «в сети»; «Изменить профиль», «Мои истории», «Папки с чатами», «Оформление» (авто / светлая / тёмная), «Конфиденциальность» (заблокированные, шифрование, вход), «Уведомления», «Поддержка», «Оценить СКАМ», «О приложении», «Выйти».
  - **Карточка человека**: плитки «Чат», «Звонок», «Видео», «Без звука»; @username и «О себе»; истории; «Медиа и файлы» (фото, видео и файлы личного чата), «Общие группы», «Дать ник»; «Заблокировать».
  - **«Новый чат»** — списком: «Написать человеку», «Создать группу», «Создать канал», «Войти по ссылке» (ссылка-приглашение, код или @канал), «Новая история».
- **Список чатов сворачивается** в узкую колонку аватарок: кнопка слева в шапке чата, полоска на правом краю списка или Ctrl+Shift+E. В свёрнутом виде — логотип, поиск, кружок историй, аватарки со счётчиками непрочитанных и ваша аватарка; состояние запоминается.

## Быстрый старт

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
cp .env.example .env      # впишите URL проекта и publishable key
npm run dev               # http://localhost:5173
```

### Без Node.js (Windows)

Если сайт уже собран и в проекте есть папка `dist`, дважды щёлкните `start-skam.cmd`. Запустится маленький сервер на PowerShell (`scripts/serve.ps1`) и откроется http://localhost:5173. Окно не закрывайте, пока пользуетесь мессенджером. Ключи Supabase при этом уже вшиты в сборку, поэтому `.env` не нужен.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер с горячей перезагрузкой |
| `npm run build` | проверка типов (`tsc`) и production-сборка в `dist/` |
| `npm run preview` | локальный просмотр сборки на http://localhost:4173 (с service worker) |
| `npm run typecheck` | только проверка типов |
| `npm run icons` | пересоздать PNG-иконки PWA из логотипа |
| `npm run legal` | пересобрать `public/terms.html` и `public/privacy.html` из `legal/*.md` (делается и само перед `dev` и `build`) |

## Настройка Supabase

1. **Ключи.** Project Settings → API Keys: `VITE_SUPABASE_URL` и publishable key (`sb_publishable_…`) или legacy anon key. Это публичные ключи: они попадают в браузер, а данные защищают RLS-политики. **Service role / secret key в `.env` не кладите никогда.**
2. **Схема базы.** Примените миграции из `supabase/migrations` по порядку: SQL Editor → вставить файл → Run (или `supabase db push`). Скрипты идемпотентные, повторный запуск безопасен.
3. **Адреса для входа.** Authentication → URL Configuration:
   - Site URL — адрес, где живёт приложение (для разработки `http://localhost:5173`);
   - Redirect URLs — добавьте `http://localhost:5173/**` и адрес продакшена.
4. **Письма с кодом.** Authentication → Emails → Templates: вставьте шаблоны из `supabase/templates/` в «Magic link or OTP» и «Confirm sign up» (тема письма написана в первой строке файла). Главное в письме — код `{{ .Token }}`, кнопка-ссылка идёт запасным вариантом; ниже тот же текст продублирован по-английски. В проекте «СКАМ» шаблоны уже стоят.
5. **Длина кода.** Authentication → Sign In / Providers → Email → «Email OTP length». Приложение ждёт 8 цифр; если поменяете, задайте `VITE_EMAIL_OTP_LENGTH` при сборке.
6. **Свой SMTP — обязательно для реальных пользователей.** Встроенная почта Supabase шлёт письма только участникам вашей команды в Supabase и не больше двух в час. Authentication → Emails → SMTP Settings (на своём сервере — `SMTP_*` в `.env`, см. `server/README.md`). Сервер СКАМ отправляет письма через почтовый сервис Selectel: `smtp.mail.selcloud.ru`, порт 1126 (STARTTLS), логин и пароль из карточки ресурса, отправитель `noreply@skam-messenger.ru` (домен подтверждён записями TXT, DKIM, SPF и DMARC). Для Яндекса:
   - Sender email — ваш ящик (например, `skam.messenger@yandex.com`), Sender name — «СКАМ»;
   - Host `smtp.yandex.ru`, Port `465`, Username — тот же адрес;
   - Password — **пароль приложения**: id.yandex.ru → Безопасность → Пароли приложений → «Почта». В настройках Яндекс Почты → «Почтовые программы» включите доступ по IMAP и «Пароли приложений».
   - Затем Authentication → Rate Limits → поднимите «emails per hour» (например, до 100).
7. **TURN-сервер для звонков (по желанию, но желательно).** Звонки идут напрямую между участниками; адреса друг друга они узнают через публичные STUN-серверы Google и Cloudflare. Из некоторых сетей (часть мобильных операторов, корпоративные сети) напрямую не пробиться — тогда нужен TURN-ретранслятор (например, свой coturn или облачный Metered / Cloudflare Calls TURN). Задайте при сборке `VITE_TURN_URL` (через запятую, например `turn:turn.example.com:3478,turns:turn.example.com:5349`), `VITE_TURN_USERNAME` и `VITE_TURN_CREDENTIAL` — в `.env` или в GitHub → Settings → Secrets and variables → Actions → Variables. Звук и видео через TURN остаются зашифрованными (DTLS-SRTP), но учтите: эти логин и пароль попадают в браузер.
8. **Поддержка — письма на ящик СКАМ.** Обращения из кнопки «Поддержка» отправляет Edge Function `support` (`supabase/functions/support`): она сохраняет обращение в `support_requests` и шлёт письмо с `noreply@skam-messenger.ru` на ящик поддержки `skam.messenger@yandex.com`, Reply-To — почта человека. На сервере СКАМ её раскладывает `server/build.sh`, переменные — в `functions.environment` файла `docker-compose.skam.yml`; в облаке Supabase — `supabase functions deploy support` и **Edge Functions → Secrets**:
   - `SMTP_USER` и `SMTP_PASS` — **обязательно**: логин и пароль почтового сервиса (Selectel: Login и Pass из карточки ресурса);
   - по желанию `SMTP_HOST` / `SMTP_PORT` (по умолчанию `smtp.mail.selcloud.ru` / `1127`, TLS сразу; Яндекс — `smtp.yandex.ru` / `465`), `SMTP_FROM` (по умолчанию `noreply@skam-messenger.ru`), `SUPPORT_TO` (по умолчанию `skam.messenger@yandex.com`).
   Пока пароль не задан, обращения всё равно принимаются и копятся в базе; после первого удачного письма функция дошлёт их сама (до 5 попыток в течение недели). Почему письмо не ушло — в колонке `last_error`.
9. **Вход через Яндекс ID и VK ID (по желанию).** Работает через Edge Function `oauth-login` (`supabase/functions/oauth-login`, `verify_jwt = false` — ею пользуются до входа). На сервере СКАМ её раскладывает `server/build.sh`, ключи задаются в `functions.environment` файла `docker-compose.skam.yml`; в облаке Supabase — `supabase functions deploy oauth-login --no-verify-jwt` и **Edge Functions → Secrets**. Адрес возврата у обоих провайдеров — сам сайт: `https://skam-messenger.ru/` (и `http://localhost:5173/` для разработки). Кнопка на экране входа появится сама, когда ключи заданы.
   - **Яндекс ID:** oauth.yandex.ru → «Создать приложение» → «Веб-сервисы»; Redirect URI — `https://skam-messenger.ru/` (и `http://localhost:5173/`); доступы «Яндекс ID»: адрес почты, имя и фамилия, портрет. Затем секреты `YANDEX_CLIENT_ID` (ClientID) и `YANDEX_CLIENT_SECRET` (Client secret).
   - **VK ID:** id.vk.ru → кабинет «VK ID для бизнеса» → создать приложение, платформа «Web»; базовый домен `skam-messenger.ru`, доверенный Redirect URL — `https://skam-messenger.ru/`; в доступах — почта. Затем секрет `VK_CLIENT_ID` (ID приложения). Секретный ключ не нужен: вход защищён PKCE.
   - Если сайт открывается с другого адреса, перечислите адреса через запятую в секрете `OAUTH_REDIRECT_URLS` (каждый — с `/` в конце, так же, как в настройках провайдера).
   - GitHub и Discord в Supabase → Authentication → Sign In / Providers лучше выключить: кнопок на сайте уже нет, но сам вход Supabase через них ещё работает.
   - Один человек — один аккаунт: функция ищет аккаунт сначала по прежнему входу через этого провайдера (`private.oauth_links`), затем по той же почте. Если почта у провайдера другая, получится отдельный аккаунт.
10. **Вход по телефону (по желанию).** Authentication → Sign In / Providers → Phone: включите и подключите SMS-провайдера (Twilio, MessageBird, Vonage, Textlocal). Вкладка «Телефон» на экране входа появится сама.

## Как устроена база

| Таблица | Назначение |
| --- | --- |
| `profiles` | имя и фамилия (`name` вычисляется из них), `username`, аватарка, цвет буквенного аватара, «О себе» (`bio`, до 140 символов и 5 строк), `last_seen_at` / `online_until` для статуса; создаётся триггером при регистрации вместе с подпиской на канал и чатом с ботом. Профиль целиком видят те, с кем есть общий чат; «О себе» остальным отдаёт `user_bio()` |
| `chats` | группы (`group`), личные чаты (`direct`), каналы (`channel`) и чат с ботом (`bot`); код приглашения (клиенту напрямую не виден — его отдаёт `my_chats` тем, кому можно); `is_default` — канал, на который подписывается каждый; `description`, `avatar_path` (`avatars/chat/<id>/…`), `username` — имя публичного канала (общее пространство с @username людей), `sign_messages` — подписи под постами |
| `chat_members` | участники, роль (`owner`/`admin`/`member`), права админа `rights` и кто назначил (`promoted_by`), `last_read_at` для непрочитанных и ✓✓ |
| `chat_bans` | чёрный список группы или канала; клиенту закрыт, работает через `remove_chat_member`, `unban_chat_member`, `chat_banned` |
| `messages` | сообщения; удаление мягкое (`deleted_at`). Вид (`kind`): `text`, `system`, `sticker` (`sticker` = «набор/стикер», `body` = эмодзи), `voice` и `video_note` (`media_path`, `media_mime`, `duration_ms`, `waveform`); `e2e` — зашифрованное сообщение (`enc` — шифротекст, `key_id` — ключ чата, `body` пустой; внутри — текст, вложения, стикер, голосовое или кружочек); `media` — вложения в канале и чате с ботом (`files` — описание файлов) |
| `user_keys` | открытые ключи шифрования (ECDH P-256); видят собеседники |
| `private.key_backups` | закрытый ключ, зашифрованный паролем шифрования; читает только владелец через `my_key_backup()` |
| `chat_keys` | ключи чатов (только id, автор и время — сам ключ здесь не хранится) |
| `chat_key_shares` | ключ чата, завёрнутый для каждого участника; развернуть может только получатель |
| `reactions` | реакции; `chat_id` проставляется триггером для RLS и Realtime |
| `calls` | звонки: чат, кто начал, видео или нет, когда звонили (`rung_at`), ответили и закончили; `status` — `active`, `ended`, `missed`, `declined`, `cancelled`. В чате одновременно идёт не больше одного звонка |
| `call_members` | кто в звонке (`in`), вышел (`left`) или отклонил (`declined`); микрофон, звук, камера, экран; вкладка (`device`) и пульс `seen_at` |
| `call_signals` | служебные сообщения WebRTC от участника участнику (зашифрованы ключом чата); получатель удаляет их, прочитав |
| `app_ratings` | оценка СКАМ: одна на человека, 1–5 звёзд, можно менять. Напрямую таблица закрыта — только `app_rating()` (средняя, число, распределение, моя) и `rate_app()` |
| `support_requests` | обращения в поддержку: тема, текст, сведения об устройстве, кто и когда; `mailed_at`, `attempts`, `last_error` — ушло ли письмо. Клиентам не видна; пишет `support_submit()`, отправку отмечает Edge Function |
| `sticker_packs` | неофициальные наборы стикеров: `id` (`u` + 11 hex), автор, название. Клиенту закрыта — только RPC (набор нельзя найти перебором, только по ссылке) |
| `stickers` | стикеры набора: `id` (10 символов), эмодзи, порядок. Картинка — `stickers/<набор>/<стикер>` в Storage |
| `user_sticker_packs` | какие наборы человек добавил себе (свои добавляются сами) |
| `chat_folders` | папки с чатами: название, значок, порядок, целые типы (`kinds`), выбранные (`include_ids`), исключённые (`exclude_ids`) и закреплённые в папке (`pinned_ids`) чаты, «без прочитанных» (`no_read`). Только свои; клиенту закрыта — `my_chat_layout`, `save_chat_folder`, `delete_chat_folder`, `reorder_chat_folders`, `folder_set_chat` |
| `chat_pins` | закреплённые в «Все чаты» (порядок `position`). Отдельно от `chat_members`, чтобы другие участники не видели, кто что закрепил. Только через `pin_chat` и `reorder_pinned_chats` |
| `user_nicknames` | свои ники для людей: кто дал (`owner_id`), кому (`target_id`), ник (до 64 символов, одной строкой). Видит только автор; клиенту закрыта — `my_nicknames()` (мои ники и как выглядят эти люди) и `set_nickname()` (пусто — убрать). До 1000 ников |
| `private.oauth_links` | вход через Яндекс ID и VK ID: какой аккаунт у провайдера какому аккаунту СКАМ соответствует. Читает и пишет только Edge Function `oauth-login` (через `oauth_resolve` / `oauth_link`, доступны только service_role) |
| `private.terms_acceptances` | кто какую редакцию Пользовательского соглашения и Политики конфиденциальности принял и когда (`user_id`, `version` вида `2026-10-02`, `accepted_at`). Клиенту закрыта: записывает `accept_terms(p_version)`, последнюю принятую редакцию отдаёт `my_terms()` |
| `private.app_owners` | владельцы СКАМ — только они выдают официальные галочки и могут удалить любой неофициальный набор |
| `private.verify_log` | журнал: кто, кому и когда выдал или снял галочку |
| `stories` | истории: автор, вид (`photo`, `video`, `text`), файл и превью в бакете `stories`, подпись или текст, фон, `pinned` (закреплена в профиле), `expires_at` (через 24 часа). Клиенту закрыта — только RPC |
| `story_views` | кто посмотрел историю и поставил ли «сердечко»; видит только автор (`story_viewers`) |
| `private.story_trash` | файлы удалённых и исчезнувших историй, которые ещё нужно стереть из Storage (их стирает cron на сервере) |
| `user_blocks` | кто кого заблокировал. Клиенту закрыта — `block_user`, `my_blocks`; проверки — `private.blocked_pair`, `private.direct_blocked` |
| `chat_mutes` | чаты «без звука» и до какого времени (`until`, пусто — навсегда). Только свои; клиенту закрыта — `mute_chat`, `my_mutes` |

У `profiles` и `chats` есть колонка `verified` — официальная галочка (у чатов — только у каналов). Читать её могут все, кто видит профиль или канал; менять — только `set_verified` от имени владельца СКАМ.

У `messages` есть `edited_at` (пост канала изменён) и `signature` (снимок имени автора, если в канале включены подписи; ставит триггер). В `messages` добавились `reply_to` и `fwd` — ответ и «Переслано от …» (только в канале и чате с ботом; в зашифрованных чатах они внутри шифротекста) — и `call_id` у записей о звонках (`kind = 'call'`, пишет только сервер).

Безопасность:

- RLS включён везде: чаты, участников, сообщения и реакции видят только участники чата.
- Права на колонки: клиент может вставить в `messages` только `id`, `chat_id` и `body`, а автор и время ставятся на сервере. Подделать автора или дату нельзя.
- Писать в канал могут владелец и администраторы с правом публикации (`private.can_post`). Права проверяет сервер (`private.has_right`, `private.can_touch`): группы и каналы меняются только через RPC — `create_chat`, `update_chat`, `set_chat_avatar`, `set_chat_username`, `add_chat_members` (только знакомые), `remove_chat_member`, `unban_chat_member`, `set_chat_admin`, `remove_chat_admin`, `transfer_chat_owner`, `delete_chat`, `edit_message`; публичные каналы — `search_chats`, `chat_by_username`, `channel_feed` (лента до подписки), `join_channel`. Не больше 20 новых групп и каналов в сутки на человека. Из канала «Новости СКАМ» и чата с ботом выйти нельзя; единственный владелец канала сначала передаёт права или удаляет канал, а из группы владелец выходит — права переходят старшему администратору (или участнику).
- Профили видны только собеседникам (`private.shares_chat`). Поиск `search_users` отдаёт только карточку — имя, @username, аватарку и цвет (без статуса «в сети»), от 2 символов и не больше 20 результатов за запрос. Менять можно только свои имя, фамилию, username и аватарку; время «в сети» ставит сервер через `ping()`, подделать его нельзя.
- Остальные действия идут через RPC-функции с проверками: `create_chat`, `join_chat`, `chat_by_invite`, `reset_invite`, `open_direct`, `delete_message`, `mark_read`, `leave_chat`, `my_chats`, `ping`, `search_users` (поиск по имени, фамилии или @username), `find_user` (точный @username, для старых версий приложения), `username_available`.
- Каналы Realtime приватные: `chat:<id>` слушают только участники чата (политики на `realtime.messages`).
- Аватарки лежат в публичном бакете `avatars`, но писать можно только в свою папку `<user_id>/`, до 2 МБ, только картинки.
- Голосовые и кружочки лежат в **приватном** бакете `media` по пути `<чат>/<автор>/<uuid>.webm|ogg|m4a|mp4`. Загрузить файл может только участник чата, которому можно писать, и только в свою папку; читать — только участники чата (по временным подписанным ссылкам). Ограничения формы сообщения проверяет база: голосовое до 10 минут, кружочек до 61 секунды, «волна» не больше 100 значений, путь файла совпадает с чатом и автором. При удалении сообщения автор удаляет и файл.
- Сквозное шифрование: база проверяет, что ключ чата раздаёт участник чата, только участникам и только от своего текущего открытого ключа (`chat_key_shares`), а зашифрованное сообщение ссылается на ключ этого же чата (`private.key_in_chat`). Ключи чатов создаются только в личных чатах и группах. RPC: `set_identity_key`, `my_key_backup`, `update_key_backup`, `e2e_pending`. Вложения (фото, видео, файлы, а в зашифрованных чатах — и голосовые с кружочками) лежат в бакете `media` как `<чат>/<автор>/<uuid>.bin`, до 50 МБ, всегда зашифрованными.
- Звонки: начать, войти, выйти, отклонить и сообщить о себе можно только через RPC (`call_start`, `call_join`, `call_leave`, `call_decline`, `call_ring`, `call_ping`, `my_calls`) и только в своих личных чатах и группах; не больше 8 человек и 6 новых звонков в минуту. Служебное сообщение можно отправить только от себя и только тому, кто сейчас в том же звонке (`private.call_peer_ok`), а прочитать и удалить — только адресату. Нет пульса 40 секунд — участник выбывает; в личном чате без ответа 50 секунд — «пропущенный». Вышел из чата — вышел и из его звонка.
- Оценка и поддержка: `app_ratings` и `support_requests` закрыты для клиентов целиком. Оценку ставят и читают через `rate_app` / `app_rating` (видна только сводка и своя оценка). Обращение создаёт `support_submit` от имени вошедшего и зарегистрированного человека: тема из списка, 5–4000 символов, сведения об устройстве до 2 КБ, 3 обращения за 10 минут и 10 в сутки на человека, 200 в час на всех. Забрать обращение для письма и отметить результат (`support_claim`, `support_mark`) может только Edge Function с service-ключом. Пароль SMTP живёт только в секретах Edge Functions.
- Картинки официальных стикеров — часть приложения (`public/stickers/<набор>/<стикер>.webp`), в базе хранится только ссылка «набор/стикер».
- Неофициальные стикеры лежат в публичном бакете `stickers` (WebP или PNG, до 500 КБ): картинку можно открыть по ссылке (как стикеры Telegram), а список файлов видит только автор набора. Загрузить картинку можно только в свой набор, по шаблону `u<11 hex>/<10 символов>` и не больше 130 файлов (`private.sticker_upload_ok`); стикер попадает в набор, только если картинка уже загружена (`add_sticker`). Эмодзи стикера проверяет база: 1–16 символов, без букв и пробелов. Лимиты: 50 своих наборов (10 новых в сутки), 120 стикеров в наборе, 200 добавленных наборов. RPC: `create_sticker_pack`, `rename_sticker_pack`, `add_sticker`, `set_sticker_emoji`, `remove_sticker`, `delete_sticker_pack`, `sticker_pack`, `my_sticker_packs`, `add_sticker_pack`, `remove_sticker_pack`.
- Истории: таблицы закрыты, всё через RPC — `story_feed` (лента), `user_stories` (профиль), `create_story`, `view_story`, `like_story`, `pin_story`, `delete_story`, `story_viewers`. Видимость — `private.story_visible`: автор или человек, с которым у автора личный чат (`private.has_direct`). Файлы — в **приватном** бакете `stories` (`<автор>/<id>.webp|jpg|mp4|webm|mov` и превью `<id>_t.jpg`, до 50 МБ): загрузить можно только в свою папку (`private.story_upload_ok`), скачать — свои или живые (не старше суток или закреплённые) истории тех, кого видно (`private.story_file_visible`). Исчезнувшие истории убирает `private.stories_gc()` (её вызывает cron на сервере), файлы стирает `server/stories-cleanup.sh`.
- Галочки: `profiles.verified` и `chats.verified` клиент читает, но не меняет (UPDATE на `profiles` выдан только по имени, фамилии, @username и фото, UPDATE на `chats` отозван). Менять — только `set_verified(kind, id, on)`, и только если вызывающий есть в `private.app_owners`; каждое изменение пишется в `private.verify_log`. `am_app_owner()` говорит приложению, показывать ли кнопки.

## Канал «Новости СКАМ» и бот

- Канал — это бывший общий чат (`id = 00000000-0000-0000-0000-000000000001`). На него автоматически подписан каждый пользователь. Читать и ставить реакции могут все, писать — владельцы (`chat_members.role = 'owner'`) и администраторы с правом публикации (их назначают в «О канале» → «Администраторы»). Посты показываются от имени канала.
- Чтобы сделать человека автором канала, выполните в SQL Editor:

  ```sql
  update public.chat_members set role = 'owner'
  where chat_id = '00000000-0000-0000-0000-000000000001'
    and user_id = (select id from auth.users where email = 'you@example.com');
  ```

- Бот СКАМ — личный чат, который создаётся каждому при регистрации (`private.ensure_bot_chat`). В нём два приветственных сообщения, а на ответы пользователя бот реагирует триггером `private.bot_reply` («привет», «помощь», «стикеры», «галочка», «голосовое», «звонки», «шифрование», «это развод?», «спасибо», «пока»; на голубя отвечает «Голубь Свободы одобряет 🕊️», на свой стикер — «Классный стикер!», на фото, видео и файлы — отдельными фразами). Фразы легко поменять прямо в функции.

## Исключения из обязательного @username

Отдельному аккаунту (например, служебному аккаунту автора канала) можно разрешить жить без @username. Флаг `profiles.username_optional` ставит только администратор — клиенту менять его нельзя:

```sql
update public.profiles set username_optional = true
where id = (select id from auth.users where email = 'you@example.com');
```

Такой аккаунт входит в мессенджер без экрана выбора @username, пишет сообщения, а в профиле @username у него помечен как необязательный. Снять исключение — тот же запрос с `false`.

## Официальные галочки и владельцы СКАМ

Галочки выдают владельцы СКАМ — те, кто записан в `private.app_owners`. Список заполняется вручную в SQL Editor (в миграциях его нет, чтобы у каждой копии СКАМ были свои владельцы):

```sql
insert into private.app_owners (user_id)
select id from auth.users where email = 'you@example.com';
```

После этого в приложении (обновите страницу) у владельца появятся кнопка «Выдать галочку» в профиле любого человека (профиль открывается из чата, списка участников или поиска — нажмите на имя или фото) и переключатель «Официальная галочка» в «О канале». Убрать владельца — `delete from private.app_owners where user_id = …`.

Галочку можно поставить и из SQL Editor, например своему аккаунту:

```sql
update public.profiles set verified = true
where id = (select id from auth.users where email = 'you@example.com');
```

У канала «Новости СКАМ» галочка стоит с миграции `verified_and_stickers`, у чата с ботом СКАМ она всегда (её подставляет `my_chats`). Выдавать галочки можно людям и каналам; группам — нет.

## Стикеры: официальный набор и свои

Свои (неофициальные) наборы пользователи делают прямо в приложении — ничего собирать не нужно (см. «Что умеет»). Владелец СКАМ может удалить любой неофициальный набор: откройте его (нажмите на стикер в чате или по ссылке) → «Удалить набор (модерация)».

Официальный набор — часть приложения. Чтобы добавить ещё один официальный:

1. Положите картинки в `public/stickers/<набор>/<стикер>.webp` — квадрат 256×256 (или 512×512) с прозрачным фоном. Имена — латиница, цифры и `_`, до 32 символов (так требует база).
2. Опишите набор в `src/lib/stickers.ts`: подпись и эмодзи каждого стикера (первый эмодзи уходит в сообщение и виден в списке чатов, остальные — для подсказок при наборе).

Официальный набор «Голубь свободы» вырезан из листа стикеров со светлым и тёмным фоном: прозрачность вычислена по разнице двух фонов, поэтому края и полупрозрачные детали (пар над чашкой) точные.

## Пользовательское соглашение и Политика конфиденциальности

Тексты лежат в `legal/terms.md` и `legal/privacy.md`. Скрипт `scripts/legal-pages.mjs` (без зависимостей) собирает из них `public/terms.html` и `public/privacy.html`: содержание, шапка с логотипом, ссылка на соседний документ, тема как в приложении. Ссылки вида `https://skam-messenger.ru/…` внутри документов становятся относительными, поэтому страницы работают и на сервере, и локально. Скрипт запускается сам перед `npm run dev` и `npm run build`; вручную — `npm run legal`.

Как выпустить новую редакцию:

1. Поправьте `legal/*.md` и строку «Редакция от …» в обоих файлах.
2. Если изменения существенные (права, обязанности, состав данных, цели) — поставьте ту же дату в `LEGAL_VERSION` в `src/lib/legal.ts`. При следующем входе каждый увидит экран «Мы обновили правила» и примет новую редакцию. Мелкие правки (опечатки, ссылки) — без смены `LEGAL_VERSION`.
3. Соберите и опубликуйте сайт. Если изменения ограничивают права пользователей, предупредите о них не позже чем за 10 дней (п. 11.2 Соглашения), например постом в «Новостях СКАМ». Прошлые редакции остаются в истории git — это и обещает п. 11.4.

Почему галочка звучит как «принимаю Соглашение и **ознакомлен(а)** с Политикой», а не «даю согласие на обработку персональных данных»: СКАМ обрабатывает данные, чтобы исполнить Соглашение (п. 5 ч. 1 ст. 6 152-ФЗ), отдельное согласие для этого не нужно. А с 1 сентября 2025 года согласие на обработку, если оно всё же берётся, должно быть отдельным документом и не может быть частью соглашения или галочки «принимаю всё».

Принятие записывается в `private.terms_acceptances` через `accept_terms` (миграция `20261002140258_terms_acceptance`). Если узнать принятую редакцию не удалось (нет сети), экран правил не показывается и приложение открывается как обычно — спросит в следующий раз.

## PWA

`public/manifest.webmanifest`, `public/sw.js` и иконки в `public/icons/`: обычные, maskable и apple-touch-icon. Иконки рисует из логотипа скрипт `scripts/gen-icons.mjs` без внешних зависимостей. Он запускается сам перед `npm run dev` и `npm run build`, если иконок ещё нет; пересоздать их вручную можно командой `npm run icons`. Service worker включается только в production-сборке: оболочка приложения открывается даже без сети, а запросы к Supabase никогда не кэшируются. Страницы документов кэшируются под своим адресом и тоже открываются без сети.

Чтобы установить приложение на телефон, его нужно открыть по **HTTPS**. Основной сайт — https://skam-messenger.ru; для своей копии разверните `dist/` на любом HTTPS-хостинге и добавьте этот адрес в Redirect URLs в Supabase. Дальше: Android/Chrome → «Установить приложение», iPhone/Safari → «Поделиться» → «На экран “Домой”».

## Свой сервер и старый адрес

СКАМ работает на VDS Selectel в Москве: self-hosted Supabase в Docker (Postgres, Auth, Storage, Realtime, Edge Functions, Studio) за Caddy с HTTPS. Адреса: `skam-messenger.ru` — сайт, `api.skam-messenger.ru` — API. Сервер сам забирает новые коммиты из `main` (раз в 5 минут) и пересобирает сайт, шаблоны писем и функции; базу и файлы каждую ночь сохраняет в резервную копию. Письма уходят через почтовый сервис Selectel с адреса `noreply@skam-messenger.ru`. Всё это, включая скрипты, — в [`server/`](server/README.md).

Миграции базы на сервер сами не приходят: их применяют к серверу (Studio, `psql` или MCP Supabase), как раньше к облачному проекту. Политики Storage и Realtime и триггер в `auth` может создать только `supabase_admin` — они в `server/managed.sql`, применяет их `sh /opt/skam-test/src/server/apply-managed.sh` (он же ставит cron уборки историй).

GitHub Pages теперь только перенаправляет со старого адреса `https://artuxay.github.io/SKAM/` на новый, сохраняя путь и параметры (`?join=…`, `?stickers=…`), и снимает старый service worker. Это страница `pages-redirect/` и workflow `.github/workflows/deploy.yml`.

src/app/media.ts            голосовые и кружочки в ленте: подписанные ссылки, плеер, круглые видео
