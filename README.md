# СКАМ

**Системный Координированный Альтернативный Мессенджер.** Новый виток в развитии русских интернациональных мессенджеров и безопасный аналог МАКС, который будет ловить даже в туалете, а не только на парковке.

Не развод, а мессенджер.

Веб-приложение на **Vite + TypeScript** без фреймворка и **Supabase** (Postgres + RLS, Auth, Realtime, Storage). Ставится на телефон как PWA.

## Что умеет

- Вход по почте: ссылка (magic link) или одноразовый код из письма — удобно в установленном PWA.
- Профиль: имя, аватарка (обрезается до квадрата 256×256 и загружается в Supabase Storage), выбор темы: авто, светлая или тёмная.
- Чаты: общий чат для всех, групповые чаты с приглашением по ссылке, личные чаты («Написать» в карточке участника).
- Сообщения: реакции 👍 😂 🔥 😱 🤡, удаление своих сообщений, ссылки кликабельны, подгрузка истории при прокрутке вверх.
- Непрочитанные: счётчики в списке чатов, число в заголовке вкладки и на иконке PWA, отметки ✓ / ✓✓ (прочитано).
- Realtime: новые сообщения, реакции и изменения приходят сразу, есть «печатает…» и «кто в сети» (Presence). Если WebSocket недоступен, приложение подтягивает изменения опросом раз в 8 секунд.
- Дизайн из прототипа `skam.html`: логотип, палитра, светлая и тёмная тема, мобильная вёрстка.

## Быстрый старт

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
cp .env.example .env      # впишите URL проекта и publishable key
npm run dev               # http://localhost:5173
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер с горячей перезагрузкой |
| `npm run build` | проверка типов (`tsc`) и production-сборка в `dist/` |
| `npm run preview` | локальный просмотр сборки на http://localhost:4173 (с service worker) |
| `npm run typecheck` | только проверка типов |

## Настройка Supabase

1. **Ключи.** Project Settings → API Keys: `VITE_SUPABASE_URL` и publishable key (`sb_publishable_…`) или legacy anon key. Это публичные ключи: они попадают в браузер, а данные защищают RLS-политики. **Service role / secret key в `.env` не кладите никогда.**
2. **Схема базы.** Примените миграции из `supabase/migrations` по порядку: SQL Editor → вставить файл → Run (или `supabase db push`). Скрипты идемпотентные, повторный запуск безопасен.
3. **Адреса для входа.** Authentication → URL Configuration:
   - Site URL — адрес, где живёт приложение (для разработки `http://localhost:5173`);
   - Redirect URLs — добавьте `http://localhost:5173/**` и адрес продакшена.
4. **Письма (по желанию, но полезно).** Authentication → Emails: вставьте шаблоны из `supabase/templates/` в «Magic Link» и «Confirm signup». В них есть русский текст и код `{{ .Token }}` для входа по коду.
5. **Почта для реальных пользователей.** Встроенная почта Supabase отправляет письма только адресам участников вашей команды в Supabase, и не больше пары писем в час. Для остальных подключите свой SMTP: Authentication → Emails → SMTP Settings (Resend, Mailgun, Яндекс 360 и т.п.).

## Как устроена база

| Таблица | Назначение |
| --- | --- |
| `profiles` | имя, путь к аватарке, цвет буквенного аватара; создаётся триггером при регистрации |
| `chats` | группы (`group`) и личные чаты (`direct`); код приглашения; общий чат `is_default` |
| `chat_members` | участники, роль (`owner`/`member`), `last_read_at` для непрочитанных и ✓✓ |
| `messages` | сообщения; удаление мягкое (`deleted_at`) |
| `reactions` | реакции; `chat_id` проставляется триггером для RLS и Realtime |

Безопасность:

- RLS включён везде: чаты, участников, сообщения и реакции видят только участники чата.
- Права на колонки: клиент может вставить в `messages` только `id`, `chat_id` и `body`, а автор и время ставятся на сервере. Подделать автора или дату нельзя.
- Остальные действия идут через RPC-функции с проверками: `create_chat`, `join_chat`, `chat_by_invite`, `reset_invite`, `open_direct`, `delete_message`, `mark_read`, `leave_chat`, `my_chats`.
- Каналы Realtime приватные: `chat:<id>` слушают только участники чата, `online` — все вошедшие (политики на `realtime.messages`).
- Аватарки лежат в публичном бакете `avatars`, но писать можно только в свою папку `<user_id>/`, до 2 МБ, только картинки.

## PWA

`public/manifest.webmanifest`, иконки в `public/icons/` (сгенерированы из логотипа, включая maskable и apple-touch-icon), `public/sw.js`. Service worker включается только в production-сборке: оболочка приложения открывается даже без сети, а запросы к Supabase никогда не кэшируются.

Чтобы установить приложение на телефон, его нужно открыть по **HTTPS**. Разверните `dist/` на Vercel, Netlify, Cloudflare Pages или GitHub Pages и добавьте этот адрес в Redirect URLs в Supabase. Дальше: Android/Chrome → «Установить приложение», iPhone/Safari → «Поделиться» → «На экран “Домой”».

## Структура

```
index.html                  разметка-оболочка, SVG-логотип, мета-теги PWA
src/main.ts                 запуск: тема, приглашения ?join=, роутинг вход ↔ приложение
src/styles.css              стили прототипа + новые экраны
src/lib/supabase.ts         клиент Supabase
src/lib/database.types.ts   типы схемы
src/lib/dom.ts              DOM-помощники, логотип, форматирование времени
src/lib/theme.ts            светлая/тёмная тема
src/app/login.ts            экран входа (ссылка + код)
src/app/app.ts              интерфейс: список чатов, лента, композер, диалоги
src/app/store.ts            состояние и запросы к базе
src/app/realtime.ts         Realtime: изменения в БД, presence, «печатает…», резервный опрос
src/app/pwa.ts              регистрация service worker
supabase/migrations/        SQL-схема, RLS, RPC, Realtime, Storage
supabase/templates/         шаблоны писем
public/                     манифест, иконки, service worker
```

Прототип, из которого вырос дизайн, — `skam.html`.
